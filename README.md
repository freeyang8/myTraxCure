# myTraxCure

用眼睛代替鼠标：注视即可选中段落，翻译结果直接覆盖在原文上。

[![Python](https://img.shields.io/badge/python-3.10%2B-blue.svg)](https://www.python.org/)
[![Stars](https://img.shields.io/github/stars/freeyang8/myTraxCure?style=social)](https://github.com/freeyang8/myTraxCure)

> ⚠️ **本项目是实验性质的尝试，不是可上线的产品。**
> 它用于验证"眼动 → 选区 → 翻译 → 覆盖"这条链路是否走得通，代码、参数与默认值都在持续试错中，未做稳定性、性能、并发、安全与隐私方面的工程化打磨，也**不建议**用于生产环境或关键任务。
> 眼动精度高度依赖硬件与坐姿（见下文《摄像头与人脸怎么摆》），不同机器上的表现差异可能很大；翻译质量取决于你本地选择的模型。请把它当作一个可运行的原型来读、来改。

---

## 项目简介

myTraxCure 是一个**基于眼动追踪的桌面翻译实验原型**（毕设项目），目标是验证一条链路能不能走通：用摄像头实时捕捉注视点，自动锁定正在阅读的段落，再把译文以覆盖层叠加在原文之上——即 **眼动 → 选区 → 翻译 → 覆盖**。

它的价值在于**探索与验证**，而不是提供可依赖的产品能力：眼动核心封装了 [eyetrax](https://pypi.org/project/eyetrax/) 0.4.0，翻译侧走可插拔的本地大模型引擎（当前为 Ollama），全程数据不出本机；但准确性受摄像头、光线、坐姿影响很大，效果需要现场调试，代码也一直处在"边试边改"的状态。因此它更适合两类用途：想了解眼动 + 桌面交互如何落地的学习者/研究者，以及手部操作不便的用户拿来**试玩**眼动阅读翻译的可能性。若你需要稳定、开箱即用的翻译工具，本项目并不合适。

---

## 功能特性

- **眼动追踪与启动校准引导**：摄像头实时追踪注视点，内置三态决策的启动校准流程与校准结果持久化
- **校准模型自动优选**：14 点密集采样 + 按注视点分组的 5 折交叉验证，在 ridge / elastic_net / linear_svr / tiny_mlp 中自动挑选验证误差最小的回归模型
- **头部姿态门控**：yaw / pitch 超过 15° 时丢弃该帧并重置驻留判定，避免歪头时红点乱跳、误触发锁定
- **凝视稳定判定与段落锁定**：段落级众数判定 + 矩形锁定 + 磁滞去抖，避免误触发
- **逐句步进阅读（默认）**：一屏 N 句，滚轮 / ↑↓ / PgUp / PgDn 一次走一句，句子即凝视与翻译单位，命中率明显高于整页版式
- **后台预翻译**：加载文档后按阅读顺序预翻译前 N 段并写入缓存，按空格时直接命中缓存、即时出译文
- **空格触发翻译 / Esc 取消**：键鼠操作极简，无需点击
- **可插拔翻译引擎**：工厂模式切换后端，当前内置 Ollama 本地翻译，后期可接入内置模型
- **鼠标模式降级兜底**：眼动不可用时自动降级为鼠标模拟注视，保证可用性

## 技术栈

- **GUI**：PyQt6
- **眼动核心**：eyetrax 0.4.0（封装复用）
- **人脸/虹膜检测**：MediaPipe FaceLandmarker
- **注视回归模型**：scikit-learn（ridge / elastic_net / linear_svr / tiny_mlp）
- **滤波**：OpenCV KalmanFilter + EMA + KDE 置信轮廓
- **文件解析**：PyMuPDF（PDF）/ python-docx（Word）
- **翻译**：Ollama 本地大模型（可插拔架构）
- **缓存**：SQLite

## 快速开始

### 环境要求

- Python >= 3.10
- 笔记本摄像头即可（用于眼动追踪）
- NumPy 必须 < 2（本项目锁定 1.26.4，与 eyetrax 兼容）
- 可选：Ollama（本地翻译后端）

### 安装与运行

```bash
# 克隆项目
git clone https://github.com/freeyang8/myTraxCure.git

# 进入目录
cd myTraxCure

# 创建并激活虚拟环境
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # Linux / macOS

# 安装依赖
pip install -r requirements.txt

# 启动应用
python main.py
# 或
python -m mytraxcure
```

## 使用说明

### 一、摄像头与人脸怎么摆（直接影响命中率，建议先看）

眼动回归模型是"照着校准时的姿态"学的：校准时人脸在画面里的位置，就是它最准的位置。位置一变，虹膜特征分布就跟着变，红点会整体偏移，锁定段落自然更容易落空。

- **摄像头要居中摆放**：把摄像头放在显示器**正上方或正下方居中**的位置，镜头朝向屏幕中心，不要偏在屏幕一侧、也不要斜着照。外接屏时别把摄像头架在笔记本那一侧。
- **人也要居中**：坐正，让**脸（尤其是双眼）保持在摄像头画面的正中央**，不要贴左/右/上/下边缘。人偏出画面中心会让预测系统性偏移。
- **距离 50–70 cm**，正对屏幕，头部大致在屏幕竖直中线上；眼睛与屏幕上沿齐平或略高。
- **校准后保持同一坐姿**：大范围移动身体、换椅子高度、或转头超过 15° 都会被头姿门控暂停锁定（此时不会误选，但也暂时选不中）。
- **环境光稳定**：避免侧向强光、逆光和忽明忽暗，虹膜检测抖动会直接变成红点抖动。
- **换环境要重新校准**：校准文件按 `用户 + 摄像头 + 屏幕分辨率` 命名保存，换摄像头或改分辨率后需重新校准。

### 二、先确认摄像头权限已打开（Windows + 杀毒软件）

程序启动就要取摄像头，权限没开的话最典型的表现是：画面全黑、`CameraThread` 报错、或直接降级成鼠标模式。**跑之前请先按下面两条查一遍。**

**1）Windows 隐私权限：设置 → 隐私和安全性 → 相机**

- 打开「**相机访问**」总开关；
- 打开「**让应用访问你的相机**」；
- 关键的一步：打开「**让桌面应用访问你的相机**」——Python 属于桌面应用，只开 UWP 开关对它无效；
- 若在「最近访问」里能看到被拒记录，说明确实被拦了；
- 也可以通过「设置 → 隐私和安全性 → 相机」页面底部确认开关状态；改动后建议重启程序。

**2）杀毒软件 / 安全软件的摄像头防护**

- **Windows 安全中心**：检查「病毒和威胁防护 → 勒索软件防护（受控文件夹访问）」是否阻止了程序；「应用和浏览器控制」里若有摄像头拦截提示，需放行；
- **第三方安全软件**（360、火绒、腾讯电脑管家等）普遍有「**摄像头防护 / 隐私保护**」功能，会默认拦截未知程序调用摄像头，需要在弹窗中选「允许」，或在其「信任区 / 白名单」里加入本项目的 Python：
  - 虚拟环境解释器，如 `E:\...\myTraxCure\.venv\Scripts\python.exe`；
  - 若用 `python main.py`，则是对应你系统里那个 `python.exe`；
- 部分软件只拦截"首次调用"，允许一次后不再提示；如果换过 Python 版本或重建过 `.venv`，需要重新放行。

> 权限没配好也不用担心程序卡死：取不到摄像头时会自动降级为**鼠标模式**（状态栏显示"模式: 鼠标"），文档浏览和翻译仍可正常使用，只是注视点改由鼠标位置模拟。

### 三、首次启动与校准

> 首次启动会自动开启 **14 点校准**，校准后还会收集一轮降噪数据用于估计滤波噪声，整体耗时较长（约 1 分钟），请耐心等待并保持头部居中不动。
> 之后再次启动，若检测到已有校准文件，会弹窗询问是否重新校准：选"否"直接沿用。
> 若摄像头不可用，程序会自动降级为鼠标模式，不会卡住。

### 四、操作方式

1. `文件 → 打开文件…` 打开 PDF / Word / TXT，文档会按窗口宽度重排；
2. 注视想读的句子/段落，**蓝框锁定**后按 **空格** 翻译，**Esc** 取消译文浮层；
3. 逐句步进模式下：**滚轮** 或 **↑↓ / PgUp / PgDn** 一次走一句；
4. 菜单 `模式`：`启动眼动` / `鼠标模式` / `逐句步进阅读`（勾选框，可切回连续滚动）；
5. 菜单 `设置 → 眼动滤波…`：拖动滑条调平滑强度 `ema_alpha`（向右更平滑但略滞后，向左更跟手但更抖），拖动即生效，确定后写入 `config.local.json`。

#### 模型配置

`mytraxcure/core/config.py` 中的 `TranslationConfig` 类包含以下配置项：

| 参数 | 类型 | 说明 |
|------|------|------|
| `backend` | `str` | 翻译后端，当前仅 `ollama` |
| `model` | `str` | 使用的翻译模型名称（需与本地 Ollama 模型一致） |
| `ollama_url` | `str` | Ollama 服务的 API 地址（默认：http://127.0.0.1:11434） |
| `source_lang` / `target_lang` | `str` | 源语言（`auto` 自动）与目标语言（默认 `zh`） |
| `pre_translate` | `bool` | 加载文档后是否后台预翻译（默认开） |
| `pre_translate_max_segments` | `int` | 单次最多预翻译多少段（默认 30，避免整本书跑满本地模型） |
| `term_table_path` | `str \| None` | CSV 术语表路径，每行 `原文,译文` |

#### 验证连接

```bash
# 1. 确认模型已就绪（名称应与配置中的 model 一致）
ollama list

# 2. 确认服务可用（应返回已下载模型列表）
curl http://127.0.0.1:11434/api/tags
```

#### 常见问题

- **画面全黑 / 一启动就是鼠标模式**：摄像头被系统或杀毒软件拦了，见《二、先确认摄像头权限已打开》
- **红点总偏一个方向 / 老是选不中**：先检查摄像头是否居中、人是否居中（见"使用说明"第一节），再考虑重新校准
- **连接失败 / 一直重试**：Ollama 服务未启动，运行 `ollama serve` 或打开 Ollama 应用
- **提示模型不存在**：`model` 字段与 `ollama list` 的名称不一致，注意带上 `:latest` 等标签
- **翻译很慢**：换更小的模型，或确认没有其他程序占用显存/内存
- **术语翻译不统一**：准备 CSV 术语表（`原文,译文` 每行一条），将路径填入 `term_table_path`

## 本次改动（相对上个版本）

上一版只保留了"原位版式 + 段落锁定"的骨架；本次把校准、门控、阅读方式三块补齐，并按毕设验收口径重做了渲染与切分。

**1. 校准：点密度 + 回归模型优选（P1）**

- 默认校准模式改为 **14 点**（`CalibrationConfig.mode`，另支持 5 / 9 / dense(5×5) / lissajous / adaptive）
- 校准采集期间接入 **头姿门控**：yaw / pitch 超阈值或眨眼的帧直接丢弃（画面提示 `Head off-center - not recorded`），不再污染训练数据
- 校准后用**按注视点分组的 5 折交叉验证**在 ridge / elastic_net / linear_svr / tiny_mlp 中自动选模型，`model_name="auto"` 时把最优模型写进校准 pkl；结束打印验证误差
- 修正 `svr` 的说明：eyetrax 0.4.0 里 `svr` 是 `linear_svr` 的别名（线性模型），并非 RBF 核

**2. 眼动滤波：可调平滑 + 噪声微调迁入项目（P1）**

- 新增 `设置 → 眼动滤波…` 滑条：`ema_alpha` 范围 0.10–0.50，拖动实时生效，取消则精确回退原值
- 降噪采集逻辑从 eyetrax 内部迁到项目内 `smoother_adapter`（不改动 `.venv` 里的包），卡尔曼测量噪声按采集点位置方差估计

**3. 头姿门控接入主链路（P0/P1）**

- `_on_gaze_frame` 中在眨眼检查之后、回归预测之前加入头姿判断：yaw / pitch > 15° 的帧丢弃并 `detector.reset()`，防止跨间隙驻留误触发
- 刻意**不参与 roll 判定**：eyetrax 对正面人脸给出的 roll 约为 ±π，带上会误杀正常姿态

**4. 阅读体验：统一重排渲染 + 语义切分 + 后台预翻译（P2）**

- **统一重排渲染**：所有文档类型都走"按段落顺序纵向重排"的 `ReflowLayout`/`DocumentRenderer`，只渲染可视区域，命中坐标来自重排后的 bbox
- **逐句步进阅读（默认）**：新增 `StepRenderer`（`ReadingConfig.step_mode=True`），一屏只放能完整显示的 N 句、44px 大字，句子即凝视与翻译单位；`滚轮 / ↑↓ / PgUp / PgDn` 逐句步进，菜单可切回连续滚动
- **语义切分**：新增 `sentence_splitter.py` / `segmenter.py`，先按段落再按句末标点切句（含 `3.14`、`Mr.`、`U.S.` 等误切保护），超长段落自动分块
- **后台预翻译**：新增 `PreTranslator`，加载文档后按阅读顺序预翻译前 N 段（默认 30）写进同一个 SQLite 缓存，按空格时即时出译文；用户自己的请求优先，不抢占
- 命中容差随模式分化：段落模式 100px、逐句模式 200px，并被"到相邻句空隙的一半"夹住，避免跨句误选

**5. 工程清理与文档**

- 删除未实现的 `builtin_engine.py`、过时的测试猴补丁与旧代码副本，测试与演示改走真实链路
- `config.py` 注释与默认值全面对齐实现（校准模式、命中容差、阅读参数等）
- 新增模块接口文档 `docs/接口文档.html`（可离线打开，含分层架构与调用链路图）

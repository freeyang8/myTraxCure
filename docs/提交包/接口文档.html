项目概览 Overview

基于 eyetrax 的眼动驱动翻译桌面软件：用视线凝视选中外文段落，按空格即时弹出译文浮层。输入不可靠时自动降级为鼠标模式。

调用链路：启动 Call Chain

从进程入口到眼动模式就绪。校准在 Qt 事件循环创建之前完成（cv2 全屏窗口需要独占）。

main.py → mytraxcure/__main__.py → app.run()

main.py脚本入口，调用 mytraxcure.app.run()
app.run() → ConfigManager.load()读 config.local.json（纯文件 IO，无需 Qt）；缺失/损坏则回退默认配置
ensure_calibration(config) → CalibrationOutcome三态决策：沿用已有 pkl / 本次新校准 / 无校准降级
QApplication(...) → MainWindow(config, config_manager)创建 Qt 应用与主窗口，装配 viewer / feedback / overlay / 摄像头预览面板
MainWindow.start_default_mode(tune_noise)启动即进眼动；本次刚校准则先做噪声微调
MainWindow._enable_gaze_mode()内部流程见下
FallbackManager.try_enable_gaze() → GazeWrapper  |  成功则进入眼动
CalibrationStore.load(wrapper, env)  |  加载校准模型
CameraThread(camera_index).start()  |  启动摄像头采集线程
frame_ready 信号 → _on_gaze_frame / _on_camera_frame
关键点：ensure_calibration() 必须在 QApplication 之前调用 —— eyetrax 校准用 cv2 全屏窗口，与 Qt 事件循环争抢会失效。

调用链路：眼动主链路 Call Chain

从摄像头帧到蓝框锁定，是整个系统的核心数据流。

CameraThread.frame_ready → MainWindow.on_gaze_point()

CameraThread.frame_ready(frame)子线程发帧（BGR ndarray），主线程槽接收
MainWindow._on_gaze_frame(frame)主链路调度入口
GazeWrapper.extract(frame) → GazeSample提特征 + 眨眼标志 + 头部姿态(yaw/pitch/roll)
门控：blink / head_angle_allowed()丢脸、眨眼、转头(>15°) 帧直接丢弃并隐藏红点、reset 检测窗
GazeWrapper.predict(sample) → GazePoint回归模型输出物理像素坐标
SmootherAdapter.step(x, y)卡尔曼 + EMA 二次平滑
MainWindow._eyetrax_to_qt(x, y)物理像素 → Qt 逻辑像素（除以 devicePixelRatio）
GazeCursorView.set_gaze_point(x, y)绘制红色凝视点（独立顶层窗口）
MainWindow.on_gaze_point(point)与鼠标模式共用同一入口
TextMapper.is_occluded(point)窗口失焦/最小化/被遮挡 → 暂停采样
TextMapper.hit_test(point, tolerance_px)带容差命中，多候选取离凝视点最近者；未命中再走“最近块回退”
TextMapper.paragraph_union_bbox(block)聚合同 para_key 的所有块 → 并集 bbox（文档坐标）
TextMapper.document_to_screen()文档坐标 → 屏幕全局坐标
GazeDetector.update(point, block_key, block_height_px)驻留 0.6s + 众数占比 + 质心偏移 → GazeStability(stable, mode)
RegionLocker.lock_block() / lock()段落模式取并集框（超限回退）；否则 400×120 点框
FeedbackView.show_region(region)绘制蓝框；随后 detector.reset() 保证 0.6s 只触发一次

调用链路：翻译与预翻译 Call Chain

即时翻译（按空格触发）与后台预翻译共用同一份 translate_text 与同一个缓存键构造函数。

MainWindow.on_space() / _start_pre_translation()

即时翻译（用户按空格）

Keyboard Space → MainWindow.on_space()浮层已显示则关闭；否则取 _locked_region
MainWindow._trigger_translation(region)本地坐标 → 全局坐标
TextMapper.segment_key_parts() / region_key_parts()段落模式取段落文本；点模式回退区域内块拼接
make_segment_key(parts, cfg, backend) → CacheKey与预翻译共用，保证键一致
CacheStore.get(key)命中 → 直接 OverlayView.show_translation()
TranslationWorker.request(text)QThread；期间暂停预翻译
translate_text() → OllamaEngine.translate()按 max_chars_per_segment 切段，逐段请求 /api/generate（流式）
finished → _on_translation_done(result)显示浮层 + 写缓存 CacheStore.put() + 恢复预翻译

后台预翻译（加载文档后）

MainWindow.load_file(path)FileParser.parse → segment_blocks → ViewerView.load_document
MainWindow._start_pre_translation()取 mapper.segments() 前 N 段（默认 30）
PreTranslator.start() → run()QThread，自带一条 sqlite 连接
make_segment_key() → CacheStore.get()已缓存则跳过，直接报进度
translate_text() → CacheStore.put()写缓存；用户按空格时即命中
为什么两条路径要共用 make_segment_key：任何一处字段不一致，预翻译写进去的结果就永远命不中，整个预翻译等于白做。
